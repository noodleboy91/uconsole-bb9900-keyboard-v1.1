# V1.1 keyboard port

Use **bb9900-v1.1-zmk.uf2** for V1.1 hardware. The optional
**bb9900-v1.1-zmk-middle-click.uf2** uses middle click when pressing the trackpad.
**bb9900-v1.1-zmk-one-handed.uf2** provides the upstream one-handed layout.
Files without `v1.1` in their names still use the original V2.1 wiring.

This update matches **upstream v1.5.0**. Hardware testing is **partially completed
for the earlier release**, with positive user feedback. The new features and
one-handed variant have not yet been hardware-tested. It keeps the
upstream features (USB gamepad, Select-to-scroll, one-shot modifiers, kitty key,
keyboard lock and backlight controls).

## Built artifacts

All three variants compiled successfully with Zephyr SDK 0.16.8. Each UF2 is 227,328
bytes. Download them from [the releases page](https://github.com/noodleboy91/uconsole-bb9900-keyboard-v1.1/releases).

| `bb9900-v1.1-zmk.uf2` | `6257675d3ce035e01529f368ab0003316276f8c783bd6c5acbfe1600c92a393a` |
| `bb9900-v1.1-zmk-middle-click.uf2` | `4e6b4e34901df99c164e8b1d535020503431251486488d4ebc6c15230230039d` |
| `bb9900-v1.1-zmk-one-handed.uf2` | `5c3c4b5be230371ae658968bd4431ec4ed3c24f8e10b4687c9de30f6f93125af` |

Validated UF2 block headers, family, application address bounds, reset vectors
and the embedded V1.1 matrix table. Verified all nine layers and 74 bindings per
layer: standard and middle-click variants differ only in the three trackpad
bindings and B tap; one-handed differs only in the four base-layer face buttons.
The keymap and settings match upstream v1.5.0 exactly. Verified scroll speed 60,
pointer speed 120, sensor lift detection, scroll light, USB joystick and backlight
in each compiled configuration. Physical testing of the new update is pending.

The local builds explicitly selected the CMSIS, Nordic HAL and LVGL modules
from the pinned Zephyr manifest using `ZEPHYR_MODULES`. LVGL supplies Kconfig
definitions; the keyboard does not enable a display. Other chip families are
not needed for this build.

## Hardware reference

The vendor product page directs V1.1 users to the older branch of
[Bill-lulu/uc9900](https://github.com/Bill-lulu/uc9900/tree/V1.2.1).
Its `config/bb9900.overlay` differs from this project's original overlay only
in four matrix positions:

| Logical position | V1.1 | V2.1 |
| --- | --- | --- |
| Enter | row 6, column 7 | row 6, column 10 |
| Bottom row, first key after Space | row 6, column 8 | row 6, column 7 |
| Bottom row, second key after Space | row 6, column 9 | row 6, column 8 |
| Bottom row, third key after Space | row 6, column 10 | row 6, column 9 |

`BB9900_V1_1` selects that older matrix without changing the logical keymap.
GPIO assignments, trackpad bus and flash partitions match the vendor overlay.
Vendor reference commit: `139ebb58993ae99931ca648e0240f69e39408863`.

The supplied known-working `KB1V1-1V31.uf2` identifies nRF52840 family
`0xADA52840`, with application data starting at `0x1000`, matching this target.
Its SHA-256 is
`994fbf09a2a2b1e19a7a338d8c9047645fdfb59aef0148cb55eb6a42b9fb4918`.
This header check establishes the firmware family and address, not full hardware
compatibility. No conversion to `.bin` is needed.

The complete 77-entry, 32-bit matrix lookup table from the vendor's older
overlay also matches the supplied stock firmware at flash address `0x330bc`.
The V2 table is absent. Conversely, the supplied `bb9900-zmk.uf2` contains the
V2 table (at `0x1660c`) and not the V1 table.

## Build

The ZMK fork is pinned in `config/west.yml` to
`c783b9e55a197392cc107a77a556893d28745688` for reproducible source selection.

After installing dependencies as described in the main README, run from the
repository root:

```sh
west build -p always -s zmk/app -d build-v1.1 -b bb9900 -- \
  -DZMK_CONFIG="$PWD/config" \
  -DDTS_EXTRA_CPPFLAGS=-DBB9900_V1_1 \
  -DZEPHYR_SDK_INSTALL_DIR="$HOME/zephyr-sdk-0.16.8"
```

Output: `build-v1.1/zephyr/zmk.uf2`. For the middle-click variant, use a separate
build directory and
`-DDTS_EXTRA_CPPFLAGS="-DBB9900_V1_1;-DMIDDLE_CLICK_TRACKPAD"`.
For one-handed, use `-DDTS_EXTRA_CPPFLAGS="-DBB9900_V1_1;-DONE_HANDED"`.
GitHub Actions builds all three V1.1 variants via `build.yaml`.

## Flash and check

Keep `KB1V1-1V31.uf2` as your known-working recovery firmware. Enter the stock
bootloader with Right Fn + `\`, then copy the V1.1 UF2 onto the keyboard's
bootloader drive, using the same procedure as for your stock firmware.

After flashing, check Enter, the three keys to the right of Space, both Fn layers,
trackpad movement/clicking, L/R buttons, Select-to-scroll, Fn+Space backlight,
Fn+G gamepad and Fn+Esc lock/unlock. The custom firmware's bootloader shortcut
is Left Alt + Right Alt + Start, or hold Left Fn, then Right Fn, then press `\`.
Use the stock UF2 to restore the previous firmware if needed.

For this update, also check B tap, slow/fast scrolling, thumb lifts, the trackpad
scroll light and the one-handed face buttons. If the light works in reverse on
your hardware, set `CONFIG_ZMK_TRACKPAD_SCROLL_LIGHT_INVERT=y` and rebuild;
`CONFIG_ZMK_TRACKPAD_SCROLL_LIGHT=n` leaves the light alone.
