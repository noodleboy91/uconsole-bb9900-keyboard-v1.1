# V1.1 keyboard port

Use **bb9900-v1.1-zmk.uf2** for V1.1 hardware. The optional
**bb9900-v1.1-zmk-middle-click.uf2** uses middle click when pressing the
trackpad. **bb9900-v1.1-zmk-one-handed.uf2** provides the upstream one-handed
layout. Files without `v1.1` in their names still use the original V2.1 wiring.
This version follows **upstream 1.6.0** and is the current release on **Latest**.
Pre-release builds append a `_PreR_<version>-v1.1` suffix; this release uses the
plain names. `v1.5.2-v1.1` and `v1.1-hardware-port.1` are kept as recovery
builds.

This port follows **upstream 1.6.0**, with sensor lift detection disabled for
V1.1. The initial v1.5.0 build caused missed movement, pointer jumps and stopping
in user testing; restoring the earlier firmware and power-cycling restored
operation. Lift detection was confirmed as the cause (see the critical warning
below) and is permanently disabled; upstream also removed it in release 1.5.1.
1.6.0 adds a trackpad light on/off key (Fn + `/`, remembered) and an easier
escape from one-shot modifiers (tap again to cancel; a click or scroll uses one
up). The 1.6.0 standard build is hardware-tested, including these two features;
the middle-click and one-handed variants build cleanly and share the same keymap
but have not been re-flashed with 1.6.0. The port keeps the upstream features
(USB gamepad, Select-to-scroll, one-shot modifiers, kitty key, keyboard lock,
backlight controls) plus the 1.5.2 horizontal scroll direction fix.

The three release assets are built by the automated Release workflow using the
official `zmkfirmware/zmk-build-arm` container, so their checksums differ from a
local Zephyr SDK 0.16.8 build. Download the current files from
[the releases page](https://github.com/noodleboy91/uconsole-bb9900-keyboard-v1.1/releases).

The **v1.6.0-v1.1** release is on **Latest** and uses plain asset names; its
standard build is hardware-tested, including the trackpad-light and one-shot
changes. The **v1.5.2-v1.1** release (plain names, hardware-tested on its

Validated UF2 block headers, family, application address bounds, reset vectors
and the embedded V1.1 matrix table. Verified all nine layers and 74 bindings per
layer: standard and middle-click variants differ only in the three trackpad
bindings and B tap; one-handed differs only in the four base-layer face buttons.
The keymap matches upstream exactly. Settings match except for
`CONFIG_INPUT_A320_OFN_ENGINE=0x00`, which disables sensor lift-detection
programming. Scroll speed 60, pointer speed 120, scroll light, USB joystick and
backlight are retained. The 1.6.0 release adds the trackpad-light behavior and
the one-shot cancel-on-retap / release-on-mouse options; all three variants
build cleanly, and the standard build is hardware-tested, including these
changes.

The local builds explicitly selected the CMSIS, Nordic HAL and LVGL modules
from the pinned Zephyr manifest using `ZEPHYR_MODULES`. LVGL supplies Kconfig
definitions; the keyboard does not enable a display. Other chip families are
not needed for this build.

## Hardware reference

The vendor product page directs V1.1 users to the older branch of
[Bill-lulu/uc9900](https://github.com/Bill-lulu/uc9900/tree/V1.2.1).
Its `config/bb9900.overlay` differs from this project's original overlay only
in four matrix positions:

| Logical position | V1.1 | V2.1 |
| --- | --- | --- |
| Enter | row 6, column 7 | row 6, column 10 |
| Bottom row, first key after Space | row 6, column 8 | row 6, column 7 |
| Bottom row, second key after Space | row 6, column 9 | row 6, column 8 |
| Bottom row, third key after Space | row 6, column 10 | row 6, column 9 |

`BB9900_V1_1` selects that older matrix without changing the logical keymap.
GPIO assignments, trackpad bus and flash partitions match the vendor overlay.
Vendor reference commit: `139ebb58993ae99931ca648e0240f69e39408863`.

The supplied known-working `KB1V1-1V31.uf2` identifies nRF52840 family
`0xADA52840`, with application data starting at `0x1000`, matching this target.
Its SHA-256 is
`994fbf09a2a2b1e19a7a338d8c9047645fdfb59aef0148cb55eb6a42b9fb4918`.
This header check establishes the firmware family and address, not full hardware
compatibility. No conversion to `.bin` is needed.

The complete 77-entry, 32-bit matrix lookup table from the vendor's older
overlay also matches the supplied stock firmware at flash address `0x330bc`.
The V2 table is absent. Conversely, the supplied `bb9900-zmk.uf2` contains the
V2 table (at `0x1660c`) and not the V1 table.

## ⚠️ CRITICAL WARNING: DO NOT ENABLE LIFT DETECTION ON V1.1

**Sensor lift detection (`CONFIG_INPUT_A320_OFN_ENGINE=0xA0`) is permanently
incompatible with V1.1 hardware.** Enabling this feature causes severe trackpad
malfunctions including:

- Missed or delayed movements
- Pointer jumps and erratic behavior
- Complete trackpad unresponsiveness

This has been tested multiple times and confirmed broken. The setting must
remain at `CONFIG_INPUT_A320_OFN_ENGINE=0x00` for all V1.1 firmware builds.
This is a known hardware incompatibility that cannot be worked around.

**Do not re-enable this feature for V1.1 under any circumstances.**

## Build

The ZMK fork is pinned in `config/west.yml` to
`4434c42f40cfff4b3f48478dc79a31157941320b` (upstream 1.6.0: trackpad light key,
one-shot cancel and clear on mouse use) for reproducible source selection.

After installing dependencies as described in the main README, run from the
repository root:

```sh
west build -p always -s zmk/app -d build-v1.1 -b bb9900 -- \
  -DZMK_CONFIG="$PWD/config" \
  -DDTS_EXTRA_CPPFLAGS=-DBB9900_V1_1 \
  -DZEPHYR_SDK_INSTALL_DIR="$HOME/zephyr-sdk-0.16.8"
```

Output: `build-v1.1/zephyr/zmk.uf2`. For the middle-click variant, use a separate
build directory and
`-DDTS_EXTRA_CPPFLAGS="-DBB9900_V1_1;-DMIDDLE_CLICK_TRACKPAD"`.
For one-handed, use `-DDTS_EXTRA_CPPFLAGS="-DBB9900_V1_1;-DONE_HANDED"`.
GitHub Actions builds all three V1.1 variants via `build.yaml`.

## Flash and check

Keep `KB1V1-1V31.uf2` as your known-working recovery firmware. Enter the stock
bootloader with Right Fn + `\`, then copy the V1.1 UF2 onto the keyboard's
bootloader drive, using the same procedure as for your stock firmware.

After flashing, check Enter, the three keys to the right of Space, both Fn layers,
trackpad movement/clicking, L/R buttons, Select-to-scroll, Fn+Space backlight,
Fn+G gamepad and Fn+Esc lock/unlock. The custom firmware's bootloader shortcut
is Left Alt + Right Alt + Start, or hold Left Fn, then Right Fn, then press `\`.
If the firmware has hung and neither shortcut responds, use the **physical reset
button** on the underside of the keyboard PCB next to the crystal — small and
unlabeled, and possibly under kapton tape (peel the tape back or press through
it). Pressing it once enters bootloader mode even when the keyboard is
unresponsive; this is the recovery path used to un-brick the keyboard during
testing. With the physical method, connect the keyboard to another PC with the
**USB-to-POGO adapter that came with the board** and copy the `.uf2` file onto
the drive that pops up when bootloader mode starts.
Use the stock UF2 to restore the previous firmware if needed.

After flashing over the initial v1.5.0 firmware, **fully shut down and power the
uConsole back on**. A zero engine setting leaves the sensor untouched; it does
not undo the previous volatile register value without a power cycle.

The 1.6.0 features to check: **Fn + `/`** turns the trackpad light off
and on, and the choice survives a power cycle; the light stays off while locked
(Fn + Esc) and comes back on unlock; and one-shot modifiers behave — tap Shift,
then click or scroll (it applies once, then clears), and tap Shift twice (it
cancels). Check B tap, slow/fast scrolling, thumb lifts, the trackpad scroll
light and the one-handed face buttons as before. If the light works in reverse
on your hardware, set `CONFIG_ZMK_TRACKPAD_SCROLL_LIGHT_INVERT=y` and rebuild;
`CONFIG_ZMK_TRACKPAD_SCROLL_LIGHT=n` leaves the light alone.
